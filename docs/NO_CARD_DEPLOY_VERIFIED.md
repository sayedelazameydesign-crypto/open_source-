## 8) GitHub Actions — الحكم في "التشغيل المستمر" (تحقق 2026-10-20)

### كمضيف للسيرفر ⇒ مرفوض تمامًا (خط أحمر)
- حد Job = **6 ساعات** ثم يُقتل (رسمي: docs.github.com/en/actions/reference/limits) — لا يوجد "تشغيل مستمر" أصلًا.
- لا يوجد منفذ عام (Ingress) للإنترنت — يحتاج tunnel هش.
- **مخالفة صريحة لشروط GitHub** (Additional Product Terms): استخدام Actions لـ general computing / persistent hosting — **حظر حسابات موثق** في مناقشات GitHub الرسمية 2024–2026.
- **الأخطر لنا تحديدًا:** حساب GitHub هو مفتاح رصيدك المتجدد $5/شهر في ClawCloud (شرط الـ180 يومًا) — المخاطرة بحظره تعني خسارة المكدس المجاني كله. ممنوع نهائيًا.

### كـ keep-alive (ping دوري) ⇒ غير مفيد في حالتنا
- **ClawCloud لا تنام أصلًا** — الحاوية تعمل 24/7 طالما الرصيد كافٍ؛ لا حاجة لأي ping.
- **Back4App الـ60 دقيقة نافذة صلبة لكل نشر** وليست خمولًا — الـping لا يمدّدها (مصدرهم الرسمي).

### الاستخدام الصحيح والمجاني 100% ⇒ CI/CD (منفَّذ ومُختبَر فعليًا)
- المستودع **عام** (تحقق عبر API) ⇒ دقائق Actions **مجانية غير محدودة** (رسمي).
- أُضيف `.github/workflows/docker-image.yml`: بناء صورة Docker (نفس Dockerfile المنصات) + **اختبار حي للحاوية** (تشغيل فعلي + `/health` + بوابة مصادقة 401) + نشر تلقائي إلى GHCR عند الدمج في main.
- **تشغيل حقيقي ناجح** (run `39340661005`، فرع arena): `docker build` ✓ ثم الحاوية قلعت وأجابت `/health` ورفضت التوكن الخاطئ ✓ — بذلك اكتمل آخر عنصر ناقص في التحقق (بناء الصورة نفسه).
- درس تشخيصي موثق: الفشل الأول كان لأن اسم المستودع `open_source-` ينتهي بشرطة (مرجع Docker غير صالح) — عولج بتطبيع الاسم في الـ workflow دون توقف.
- حدود يجب مراعاتها: الجدولة (cron) تُعطَّل تلقائيًا بعد 60 يوم خمول بالمستودع، أدق فاصل 5 دقائق، وقد تتأخر حتى ~15 دقيقة تحت الحمل.
- للمراقبة الدورية للرابط العام: أداة مخصصة مجانية بدون بطاقة (مثل UptimeRobot) أنسب وأأمن من cron على Actions.

### ملاحظات GHCR
- **`:edge` منشورة فعليًا** (2026-10-20، run `39341172545` — كل الخطوات ✓ بما فيها Publish):
  `ghcr.io/sayedelazameydesign-crypto/open_source:edge` — صورة جاهزة لـ ClawCloud قبل الدمج في main (والـ main سينشر `:latest` تلقائيًا).
- الحزمة تُنشأ **خاصة افتراضيًا**: اجعلها عامة (Package settings → Change visibility) لتسحبها ClawCloud بلا توكن، أو أدخل بيانات Registry خاص فيها.

### "الأكشن يعيد التشغيل تلقائيًا" — الحكم النهائي حسب نوع الفصل (تحقق 2026-10-20)
1. **فصل خمول (idle)**: يوقظه أي ping — ليست حالتنا (ClawCloud لا تنام).
2. **فصل Back4App (نافذة 60 دقيقة صلبة)**: **مستحيل تقنيًا** — لا يوجد أي API عام لإعادة النشر في الخطة المجانية؛ إعادة النشر زر يدوي في اللوحة، و`autodeploy-on-push` **ميزة مدفوعة**. مستودعهم الرسمي `templates-back4app/always-on-worker` قاسها بنفسه (سبتمبر 2026): «الحاوية تُدمَّر بعد 60 دقيقة من بدء النشر — نبضة #60 ثم صمت؛ تغيير الخطة إلى Shared ($5/شهر) هو الحل الرسمي الوحيد». لا يوجد endpoint يستطيع أكشن GitHub مناداته أصلًا، وأي التفاتة هندسية = خرق للاستخدام العادل.
3. **فصل انهيار (crash)**: في ClawCloud تعيد المنصة التشغيل تلقائيًا (K8s restart + زر Restart يدوي) — لا حاجة لأكشن.

**الاستنتاج:** الحل ليس "أكشن يُعيد التشغيل" بل **منصة لا تفصل أصلًا** (ClawCloud: 24/7، رابط HTTPS ثابت، والتطبيق لدينا stateless — حالته في Supabase — فأي إعادة تشغيل عرضية تمر بلا أثر). النمط الصحيح المُفعَّل لدينا: **Actions → GHCR → ClawCloud** (نفس النمط موثق بنجاح في مشاريع خارجية).
