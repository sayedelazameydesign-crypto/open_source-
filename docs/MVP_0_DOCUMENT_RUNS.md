# MVP-0 — معالجة مستند نصي محليًا

## النطاق والحالة

تنفيذ محلي حتمي، وليس تلخيصًا دلاليًا أو اختبارًا لقدرة نموذج. لا AI أو شبكة
أو أوامر نظام في مسار معالجة المستند. واجهة عربية مستقلة: `/documents`؛ رابطها
في صفحة الوكيل. لا تغيير في عقد `POST /runs`.

الأساس المفحوص: `14db8a35d99e0c1fd15110d4cdf38f15ff20ee25`، الفرع
`arena/b25f704f-open-source`.

## العقود

جميع المسارات تستعمل مصادقة المنصة الحالية `Authorization: Bearer …`.

| الطلب | الوظيفة |
|---|---|
| `POST /document-runs?filename=input.txt` | جسم الطلب بايتات الملف **مباشرة**، وليس multipart أو JSON؛ يعيد 201 والخطة فقط |
| `GET /document-runs/{id}` | الحالة والخطة والأحداث والإحصاءات وبيانات الناتج دون نص المصدر |
| `POST /document-runs/{id}/execute` | تأكيد صريح لبدء المعالجة؛ يعيد الحالة، ولا يعيد تنفيذ مهمة مكتملة |
| `GET /document-runs/{id}/artifacts/{artifact_id}/download` | بايتات Markdown، مع Content-Disposition وnosniff وno-store |

الحالات: `RECEIVED → PLAN_READY → AWAITING_CONFIRMATION → RUNNING → SUCCEEDED / FAILED`.
تُسجل الثلاث الأولى عند الاستقبال وتعود حالة الانتظار مع الخطة، ولا تشغّل المعالجة.
الفشل نهائي في هذه النسخة؛ إعادة التنفيذ تعيد 409. حالة RUNNING لا تشغّل عملًا آخر.

### التحقق والتقرير

- ملف بامتداد `.txt` دون الثقة بـMIME؛ الاسم لا يدخل مسار تخزين ولا يعود اسمًا للناتج.
- حتى 1,048,576 بايت، والزيادة 413، مع عد البايتات الفعلية أثناء القراءة.
- UTF-8 صارم؛ الترميز غير الصالح ومحارف التحكم عدا TAB/CR/LF تعيد 422.
- الامتداد المرفوض يعيد 415؛ النص الفارغ مقبول.
- لا يوجد كاشف عام لكل الصيغ الثنائية: القبول يعني UTF-8 صالحًا وفق سياسة
  محارف التحكم المذكورة، ولا يثبت طبيعة المستند الدلالية.
- الحجم = بايتات الأصل؛ الأحرف = `len(text)`؛ الكلمات = `len(text.split())`؛
  الأسطر = `len(text.splitlines())`؛ المقتطف = `text[:500]`.
- يُدرج المقتطف ككتلة شيفرة مزاحة في Markdown، ولا يُعرض كـHTML في الواجهة.
- التقرير يحتوي المعرّف والحالة ووقت إنشاء المهمة والإحصاءات والمقتطف وحقل الأخطاء.
- يُحسب SHA-256 لبايتات الناتج النهائية ويحفظ خارج التقرير؛ يُفحص قبل التنزيل.
- الإحصاءات والمقتطف حتمية؛ بايتات التقرير تختلف بين المهام بسبب المعرّف والتوقيت.

## التخزين والخصوصية

تُستخدم `RunState.metadata` لحالة المستند وخطته/أحداثه ومصدره المؤقت؛ النتيجة في
Artifacts عبر `RunStore` الحالي، دون قاعدة ثانية أو تغيير مخطط قاعدة البيانات.
تُعاد خطة هذه النسخة الثابتة من الكود. لا تُنشأ مهمة وكيل أو تُستدعى أدواته.

للاستمرارية شغّل الخادم مع:

```sh
export CELA_RUN_STORE_URL=sqlite:///.cela/runs.db
# استخدم رموزك المحلية عبر البيئة، ولا تكتبها في الملفات أو الأوامر المشتركة.
.venv/bin/python -m os_server.cli serve --demo --host 127.0.0.1 --port 8080
```

دون هذا الإعداد يبقى افتراضي المشروع مخزنًا في الذاكرة. تضبط واجهة Next المتغيرين
`CELA_BACKEND_URL` و`CELA_API_TOKEN` على الخادم فقط؛ لا يصل الرمز إلى المتصفح.

لا يُحفظ الاسم الأصلي، ولا يُكتب المحتوى في سجلات التطبيق أو الذاكرة طويلة الأجل.
يُزال المصدر من الحالة الحالية بعد النجاح أو فشل المعالجة. **هذا ليس محوًا آمنًا**:
قد تبقى نسخ في صفحات SQLite/WAL والنسخ الاحتياطية. يبقى التقرير ومقتطفه محفوظين.
لا يوجد تشفير أو احتفاظ/حذف تلقائي ضمن هذه المرحلة؛ لا تستخدم ملفات سرية للغاية.

## حدود التشغيل — مهمة

- مستخدم موثوق واحد، **عملية Python واحدة**. قفل داخل العملية يمنع تكرار التنفيذ
  حتى بين طلبات متزامنة أو نسخ تطبيق داخل العملية؛ لا توجد مطالبة موزعة بين workers.
  لا تستخدم عدة عمليات على قاعدة مشتركة؛ هذا الضمان خارج النطاق وغير متحقق.
- إعادة إنشاء Runtime/تطبيق تستعيد المهمة المكتملة وناتجها والمهام المنتظرة.
  انقطاع العملية أثناء RUNNING لا يؤدي لإعادة تنفيذ تلقائية؛ يلزم تعافٍ مستقبلي.
- نظام ملكية متعدد المستخدمين غير موجود. كل حامل لرمز المنصة هو المستخدم الموثوق
  نفسه. التحقق يربط Artifact بالمهمة؛ لا تدّعِ عزل مستأجرين.
- وكيل Next الحالي يملك رمز المنصة على الخادم، لكنه ليس نظام دخول للمستخدم.
  استخدمه محليًا فقط، ولا تعرضه للإنترنت دون مصادقة مستخدم وحماية CSRF/Origin مستقلة.
- الحد لكل ملف فقط؛ حصص مجموع التخزين، والاحتفاظ، ومعدل الطلبات مؤجلة.
- لا ضمان بمجانية الاستضافة أو أهلية حساب أو أداء إنتاجي؛ لم يحدث نشر.
