# ADR-0021: التصعيد الآلي للمستويات — `os_agents.escalation`

**التاريخ:** 2026-10-17 · **الحالة:** مقبول ومُنفَّذ (إفراغ مؤجَّل ADR-0020 بشروطه المعلَنة)
**يُكمل:** [`ADR-0020`](0020-local-sub-agents-and-guardrails.md) — بند «التصعيد الآلي» في «المؤجَّل صراحة»

## السياق

أنجز ADR-0020 المسارات الأربعة (وكلاء فرعيون، فحص موارد، قارئ مستندات، تحقق ذاتي)، و**أجّل**
التصعيد الآلي بشرط صريح: «يحتاج إشارة «صعوبة» مُقيسة لم تُحسم». والسؤال المطروح: **متى يقرر
النظام أن المهمة ليست من شؤون الوكيل الفرعي؟** ثلاثة أحوال محتملة:

1. **صعوبة مُقدَّرة قبل التفويض** — مهمة تخطيطية أو تتجاوز سعة النموذج الخفيف: إرسالها للوكيل
   الصغير ليس جرأة بل هدر (وسوء توجيه مكلف إن رجعت بإجابة سطحية يُصدَّق بها).
2. **استنفاد محاولات الوكيل نفسه** — حدّ خطوات/زمن أو رفض موارد: إعادة التفويض نفسه هي تعريف
   الجنون، والمنسّق يجب أن يستأنف بنفسه.
3. **استنفاد حلقة التصحيح الذاتي** — `SelfCorrectionLoop` يرجع `accepted=False` عند الحدّ:
   المرحلة التالية في السُلّم ليست محاولة رابعة بنفس المخرجات بل نموذج أكبر.

شرط الإشارة تحقّق دون بناء قياس جديد: `ModelRouter.profile()` موجود ومجريب (`TaskProfile`
بإشارات تخطيط إنجليزية/عربية وعدد توكنات)، وهو **القياس نفسه** الذي يوجّه النماذج — فلا سبب
لإنفاق استدلال إضافي لاتخاذ قرار عن جدوى استدلال.

## القرار

وحدة جديدة `os_agents/escalation.py` بثلاثة مُشغّلات حتمية، والحكم كله قبل/بعد بلا نموذج:

1. **`precheck` قبل أول توكن استدلال** — ثلاث إشارات بترتيب دليل:
   * **`planning`** — `profile(task).is_planning` (نفس إشارات الراوتر: plan/research/… + خطة/ابحث/… + طول السياق).
   * **`mandate`** — فعل تعديل/تنفيذ في نص المهمة (`write|create|…|execute`، و`run`/`runs`
     **مشروطان بأداة** (the/a/an/…) لأن مفردات المستودع نفسها («run outcome ledger»، ‏`/runs`)
     قراءةٌ محضة — «شغّل|نفذ|أنشئ» العربية بلا اشترط لأنها أحادية الدلالة.
   * **`task-size`** — ‏`prompt_tokens > max_task_tokens` (افتراضي 4096، دون عتبة الراوتر 6000
     فتجيب السؤالين Different: «هل تصلح للوكيل الخفيف؟» لا «هل تستحق الطبقة الكبيرة؟»).
2. **`postcheck` بعد فشل التنفيذ** — `step bound`/`time bound` → إشارة `bounds`، ورفض الموارد →
   `resource`، وكلتاهما تعني: محاولات الوكيل منتهية، لا إعادة تفويض بلا تغيير.
3. **`from_correction`** — تحويل إرهاق `CorrectionResult` إلى تصعيد يحمل آخر مخالفات كـ`instruction`
   (نقطة تركيب الصريحة بين طبقة التحقق وطبقة التوجيه).

كل مُشغّل يرجع `EscalationDecision(escalate, signal, reason, instruction)` — والقرار بلا إجراء
 مجرد شكوى، لذا `instruction` إلزامي المضمون: «عالِجها في الحلقة الرئيسية» مع الدليل.

**الربط:** `SubAgentHub.delegate(task, *, agent="", force=False)` يستدعي `precheck` (إلا بـ`force`)
ويستدعي `postcheck` بعد الفشل؛ والنتيجة تحمل `escalation` وحقلًا محسوبًا `escalated`. أداة
`delegate_subagent` تُعيد `escalated`/`escalation_signal`/`instruction` في مخرجاتها + معامل `force`.

**`force` يتجاوز الفحص الصعوبة وحده** — قائمة الأدوات المسموحة ليست سياسة بل سياج: إجبار
وكلٍّ خفيف على «كتابة ملف» يبقى مرفوضًا عند التنفيذ ويصعّد بعد الفشل.

## ما نُفِّذ (مُختبَر — 17 اختبارًا جديدًا، بلا شبكة)

| الحال | النتيجة المُختبَرة |
| --- | --- |
| مهمة تخطيطية (إنجليزية/عربية) | رفض قبل أي استدعاء نموذج (`call_count == 0`)، إشارة `planning` |
| فعل تعديل (EN/AR) | إشارة `mandate` مع الفعل في السبب |
| تجاوز سقف التوكنات | إشارة `task-size` |
| استكشاف روتيني | **لا** تصعيد (ومنه مهمة تذكر `ledger` — لا كلام `run`) |
| حدّ خطوات/زمن بعد التشغيل | `escalated` بإشارة `bounds` وتعليم «الحلقة الرئيسية» |
| نقص موارد | إشارة `resource` |
| `force=True` | يمرّ إلى النموذج (`call_count == 1`) ولا يمسّ السياج |
| اسم وكيل مجهول | `ValueError` يبقى يُرفع حتى مع مهمة تخطيطية (الفحص بعد `pick`) |
| إرهاق `SelfCorrectionLoop` | تصعيد `correction-loop` يحمل نص المخالفات |
| قبول التصحيح | لا تصعيد |
| الأداة | `delegate_subagent` يطبع `escalated` و`instruction` في JSON |

قياس المجموعة بعد الدمج: **1086 مُجتازًا / ١ مُتخطّى اختياريًا / ٠ فشل**، و`ruff check` نظيف.

## الحدود الصريحة

* **المسار أحادي الاتجاه:** `escalation` يستورد `validation` و`router`؛ ولا شيء يستورد التصعيد
  عدا `subagents` — بلا دوريات.
* **`Platform` لم تتغيّر**: القرار يعيش في أداة التفويض حيث يقرّه المنسّق فعليًا؛ لا إخفاء
  تلقائي لمهام «صعبة» عن الوكيل الرئيسي في مستوى أعمق.
* **التصعيد ليس فشلًا في الأمان**: مهمة مُصعَّدة لم تُخترَق، أُسندت لمستوى أعلى. السياج الأمني
  (allow-list + بوابة موارد + حدود) يبقى مفروضًا على كلتا المستويتين.
* **الإشارة قواعد لا نموذج**: لاضرورة نموذج لتقدير صعوبة مهمة يُراد توفير نموذج لها. نسبة
  الإيجابيات الكاذبة محدودة بـ`force` وأزرار `planning_escalates`/`mandate_escalates`.

## المؤجَّل صراحة

* **مُصنِّف صعوبة مُتعلَّم** — لو أظهرت تقييمات `os_evals` أن القواعد تصعّد أو تمنع دونما سبب
  كافٍ، يُبنى مُصنِّف فوق مخرجات القواعد الحالية (وليس بديلاً عنها) — بقرار منفصل.
* **وكلاء فرعيون متوازون** — كما في ADR-0020؛ `delegate` ينفّذ مهمة واحدة حتى من يصعّد.
* **تصعيد بين الوكلاء الفرعيين** (explorer → auditor) — السلّم اليوم صعود فقط للمنسّق؛ تنزيلًا
  بين الأقران يحتاج أدوارًا أكثر مما تبرره الأدوات الحالية.
